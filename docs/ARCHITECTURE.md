# Architecture

## Components

| Location | Responsibility |
| --- | --- |
| `public/app.js` | Workspace routing, interface rendering and user actions |
| `public/marketing.js` | Public product and audience pages |
| `public/account.js` | Session verification and account-change detection |
| `public/db.js` | Account-scoped IndexedDB access and record transactions |
| `public/domain.js` | Formats, validation, research calculations and calendar output |
| `public/media.js` | Media inspection, canvas composition and browser exports |
| `public/archive.js`, `public/backup.js` | ZIP encoding, validation and backup preparation |
| `public/workflows.js` | Preparation presets and content-kit manifests |
| `worker/index.js` | Request routing, identity checks, security headers and static assets |
| `worker/google.js` | Drive and YouTube authorisation and read operations |
| `worker/twitch.js` | Twitch authorisation, token protection and video listing |
| `scripts/` | Local development server, Worker build and artifact validation |
| `tests/` | Handler, domain, rendering, storage and provider tests |

The application uses native browser modules and platform APIs. There is no framework build pipeline or server-side media transcoding service.

## Workspace request flow

1. The hosting gateway verifies the visitor and supplies trusted identity headers.
2. The Worker redirects unauthenticated workspace requests to the gateway's sign-in route.
3. The client reads `/api/session` and configures its database with the verified account ID.
4. Workspace actions revalidate the session through `verifyAccount`; expired or changed identities lock the database and clear in-memory state.
5. Media processing runs locally. Downloads are generated by the browser.

The gateway is a security boundary, not an optional proxy. Identity headers must not be trusted from arbitrary internet clients.

## Provider connection flow

A same-origin, authenticated request starts an OAuth transaction. The provider redirects to a server callback. The callback validates state, exchanges the code and confirms the external identity before storing encrypted credentials in HttpOnly cookies. Google connections also use PKCE. Later reads validate the connected subject and refresh expired access tokens when possible.

Connections belong to the workspace identity, provider and origin. They are browser-scoped; there is no central connection database or background scheduler.

## Build flow

`npm run build` reads all files under `public/`, embeds them in the Worker and combines the provider modules into `dist/server/index.js`. It copies the hosting manifest to `dist/.openai/hosting.json`. `npm run validate` imports the generated module and checks its default request handler.

The bundling script expects its provider import statements to retain their recognised forms. Changes to module composition must be tested against the built artifact, not just the source modules.

## Boundaries

Personal approval states are local records, not team permissions. Research metrics are user-entered observations, not connected analytics. A content-kit destination is not a publishing connection. Changing the production origin creates a separate browser storage scope and invalidates origin-bound connection cookies.
